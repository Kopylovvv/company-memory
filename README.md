# Company Memory

«Компания, которая не забывает» — проект команды для хакатона MAX.
Сохраняем опыт из рабочих сообщений и помогаем находить подтверждённые случаи,
источники и сотрудников, которые участвовали в решении проблемы.

## Текущее состояние

Работает bot-only MVP в MAX: бот сохраняет текст ремонта, показывает предложенные
YandexGPT поля как черновик, позволяет автору исправить и подтвердить случай,
затем ищет подтверждённый опыт. Исходное сообщение и подтверждённые поля хранятся
в PostgreSQL. Похожий случай — подсказка из опыта, а не диагноз. Если AI недоступен,
исходное сообщение остаётся в черновике. React-страница сейчас служит для
локальной диагностики и не является мини-приложением MAX. Контракт описан в
`contracts/README.md`; последние улучшения мобильного сценария — в PR #24.

## Назначение и сценарий

Целевой пользователь — сотрудник промышленной компании, которому нужно повторно
использовать опыт ремонта оборудования. Вместо ручного поиска по сообщениям он
получает подтверждённый коллегой случай с симптомом, действием и результатом.

1. Отправьте боту MAX текст о ремонте. Бот сохранит исходное сообщение и
   предложит поля черновика для проверки.
2. Автор исправляет неточность через `/edit <поле> <значение>` и подтверждает
   последний свой черновик через `/confirm`. `/help` показывает команды.
3. `/search <описание проблемы>` ищет подтверждённые случаи. Черновики в выдачу
   не попадают; неизвестный запрос получает честный пустой ответ.

Синтаксис без ID появится на стенде после слияния и развёртывания PR #24. До
этого `/edit` и `/confirm` требуют ID, который бот выводит в ответе.

## Быстрый запуск

Нужны Git и Docker Engine с Compose v2. Скопируйте `.env.example` в `.env`.
Для полного сценария заполните `MAX_BOT_TOKEN` токеном **тестового** бота, а для
AI-черновиков — `LLM_API_KEY` и `YANDEX_FOLDER_ID`. Не запускайте два poller с
одним токеном одновременно: локальный бот и рабочий стенд будут делить события.
Для проверки уже работающего бота локальный poller не нужен.

**Одна команда для всех локальных компонентов, включая бота:**

```sh
cp .env.example .env
docker compose --profile bot up -d --build
```

Если токена нет, `docker compose up -d --build` запускает только БД, backend и
диагностическую страницу. Бот без токена не сможет подключиться к MAX.

- Диагностическая страница: http://127.0.0.1:5173
- API и документация: http://127.0.0.1:8000/docs
- Проверка процесса API: http://127.0.0.1:8000/api/health
- PostgreSQL не опубликован наружу; у бота нет входящего порта.

Страница интерфейса должна показать «API доступен». Это проверяет связь frontend
с backend, но не MAX и не AI. Backend применяет миграции при старте контейнера.
Состав: `bot` принимает события MAX по long polling, `backend` обслуживает случаи,
`db` хранит исходные сообщения и подтверждения, `frontend` используется только
для разработки. На рабочем стенде Caddy обеспечивает HTTPS. Подробнее:
`docs/architecture.md` и `infra/production.md`.

Проверка: `docker compose --profile bot ps`. Остановка:
`docker compose --profile bot down`. Повторный запуск — та же команда `up`.
Данные БД сохраняются в именованном томе.
`docker compose down -v` удаляет локальные данные — не используйте без необходимости.

Для сборки из исходного кода нужны `backend/Dockerfile`, `frontend/Dockerfile`,
оба `.dockerignore`, `backend/uv.lock`, `frontend/package-lock.json` и
`compose.yaml`. `.env.example` не содержит рабочих секретов. Первый запуск
загружает базовые Docker-образы из реестра. Рабочий бот также зависит от внешних
API MAX и YandexGPT; если YandexGPT недоступен, текст остаётся в черновике.

### Переменные окружения

`POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` задают локальную БД;
демонстрационные значения приведены в `.env.example` и не подходят для сервера.
`MAX_BOT_TOKEN` нужен только боту. `LLM_API_KEY` и `YANDEX_FOLDER_ID` включают
YandexGPT; необязательные `YANDEX_GPT_MODEL` и `LLM_TIMEOUT_SECONDS` задают модель
и таймаут. В Docker-образе уже есть CA-бандл для MAX (`MAX_API_CA_BUNDLE`).
Production использует отдельный `.env.production` из
`infra/.env.production.example` и [инструкцию сервера](infra/production.md).
Рабочие ключи и токены не добавляются в репозиторий.

### Данные и пошаговая проверка

[Набор data/](data/README.md) полностью синтетический: оборудование, сообщения и
люди вымышлены; реальной интеграции с предприятием в MVP нет. После старта
Compose можно загрузить подтверждённые случаи и черновики одной командой:

```sh
docker compose run --rm -v "$PWD/data:/data:ro" backend .venv/bin/python -m app.ai.seed --data-dir /data
```

Повторная загрузка не создаёт копий. Для проверки основного сценария в MAX:

1. Отправьте `/help`, затем синтетическое сообщение: «На насосе Н-777 появилась
   течь фланца. Подтянули крепёж, течь прекратилась».
2. Проверьте предложенные поля; исправьте результат через
   `/edit результат течь прекратилась после подтяжки`.
3. Отправьте `/confirm`, затем `/search Н-777 течь фланца`. Ожидается
   подтверждённый случай с действием и результатом.
4. Поищите несуществующий случай: ожидается честный пустой ответ. После
   перезапуска контейнеров подтверждённый случай должен оставаться в поиске.

Если проверяется версия до PR #24, используйте полный ID в `/edit` и `/confirm`.
Поэтому перед проверкой сверьте commit стенда с commit сдаваемой версии.
Известные ограничения: бот принимает только текст; поиск по сходству формулировок
может пропустить подходящий опыт; поля AI требуют проверки человеком; бот
работает через внешние API MAX и YandexGPT. HTTP API случаев в bot-only MVP не
предназначен для публичной проверки: без подтверждённой личности он отвечает
`401`, а доступный через MAX сценарий проходит полностью в диалоге с ботом.

## Структура

```text
backend/        FastAPI, PostgreSQL, бот MAX, AI и тесты
frontend/       диагностическая React-страница
infra/          production-конфигурация и инструкции
contracts/      примеры формата данных для согласования API
data/          синтетические примеры и проверочный набор
docs/          продукт, архитектура, разработка, план, сдача
.github/        CI и шаблоны задач/pull request
compose.yaml    локальный запуск с профилем bot
```

В репозитории не должно быть токенов, паролей или реальных корпоративных документов.
`.env.example` содержит только локальные демонстрационные настройки. Не публикуйте
эту конфигурацию в интернете: публичное развёртывание — отдельная задача.
