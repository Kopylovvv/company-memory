# AI and retrieval — Макс

Два первых интерфейса для согласования с Андреем:

1. Текст источника → черновик структурированного случая с отсутствующими полями.
2. Описание проблемы → найденные подтверждённые случаи с ID и источниками.

Сохранение, авторизация, статусы и права принадлежат backend. Модель предлагает
черновик, но не подтверждает его. Не выдумывать причину, результат, оборудование,
сотрудника или ссылку. Источник — данные, а не инструкции для модели.

Для начала достаточно обычных Python-функций в этом модуле; отдельный AI-сервис
не нужен. Поставщика модели и стратегию поиска выберем на проверочном наборе.

## Что уже есть

- `dataset.py` — загрузка и проверка синтетического набора из `data/` (Issue #3):
  эталонные поля для оценки извлечения и проверочные запросы для поиска.
- `seed.py` — загрузка набора в хранилище случаев через общие правила создания и
  подтверждения; команды — в `data/README.md`.
- `search.py` — поиск похожих подтверждённых случаев (Issue #8), см. ниже.
- `search_eval.py` — оценка поиска на проверочных запросах:
  `uv run python -m app.ai.search_eval` из `backend/`.

## Поиск (Issue #8)

Хранилище (in-memory или PostgreSQL) отбирает только подтверждённые случаи, затем
`rank_cases` ранжирует их по запросу. Внешний AI и новые зависимости не нужны.

- Русские словоформы сводятся простым отсечением окончаний; синонимы ремонтной
  лексики («трясёт» → вибрация, «буксует» → проскальзывание) — через небольшой
  тезаурус `THESAURUS`. Его расширяют, когда реальная формулировка не находится,
  и после этого перезапускают оценку.
- ID оборудования распознаётся без учёта дефиса и латинских двойников букв.
- Оценка 0..1 — доля взвешенных слов запроса, найденных в случае; редкие слова
  весят больше. Если запрос называет оборудование, случаи на другом оборудовании
  получают половину оценки.
- Нужно совпадение по сути проблемы (симптом, причина, действие, результат) и
  оценка не ниже `MIN_SCORE = 0.5`, иначе — честный пустой ответ.

Результат на синтетическом наборе (19 запросов, 14 подтверждённых случаев,
top-3): попадание 12/13, честный пустой ответ 6/6, лишних результатов 0. Для
сравнения, прежний поиск подстрокой: попадание 0/13. Порог и штраф подобраны на
этом же наборе, который писала та же команда, поэтому это проверка
работоспособности, а не доказательство качества.

Известные ограничения:

- Отрицания не понимаются: «давление не поднимается» ближе к случаю «давление в
  норме, медленный ход ползуна», чем к «не набирает давление» (промах `q-07`).
- Перефразы вне тезауруса не находятся; семантический поиск через эмбеддинги
  возможен позже за тем же интерфейсом, если появится провайдер.
- Запрос только из названия оборудования («насос») даёт пустой ответ — для этого
  есть история оборудования.
- Ранжирование идёт в Python по всем подтверждённым случаям; при сотнях случаев
  это быстро, для большой базы понадобится предварительный отбор в SQL.
