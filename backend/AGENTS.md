# Backend: инструкции для AI-агентов

Сначала выполните правила из корневого `AGENTS.md`. Этот файл действует для
`backend/`.

- Сохраняйте приложение модульным монолитом FastAPI: HTTP-слой не должен
  содержать всю бизнес-логику или прямые AI-вызовы.
- Сначала согласуйте Pydantic-контракт и состояния ошибок, затем реализацию.
- Изменения PostgreSQL оформляйте воспроизводимой миграцией; не полагайтесь на
  ручное изменение локальной базы.
- Для входящих событий MAX обеспечьте проверку данных и идемпотентность.
- Внешние сервисы и AI подключайте через заменяемые адаптеры с таймаутами и
  понятной обработкой недоступности.
- Не смешивайте проверку процесса `/api/health` с будущей проверкой готовности
  БД и внешних сервисов: назначение endpoint должно оставаться явным.
- Для новой логики добавляйте тесты на успешный путь, валидацию и повтор события.
- После изменения зависимостей обновляйте `pyproject.toml` и `uv.lock` вместе.

Владелец API, БД и MAX-интеграции — Андрей. Изменения контракта должны получить
review Егора и Макса, если затрагивают frontend или AI.
