# Разработка с AI-помощниками

`AGENTS.md` хранит постоянный контекст репозитория: границы продукта, владельцев,
правила безопасности и критерии готовности. Корневой файл относится ко всему
проекту, а вложенный файл уточняет правила своей папки. Это инструкции для агента,
а не исполняемый код и не замена review.

Codex читает подходящие `AGENTS.md` при работе в репозитории. Для GitHub Copilot
добавлен `.github/copilot-instructions.md`, который направляет его к тем же правилам.
Если другой инструмент не поддерживает эти файлы автоматически, передайте ему
прямой запрос прочитать их.

## Шаблон запроса

Скопируйте шаблон и заполните значения в квадратных скобках:

```text
Работай над GitHub Issue #[номер] в репозитории company-memory.

Сначала прочитай корневой AGENTS.md, ближайший AGENTS.md для изменяемой папки,
README.md, CONTRIBUTING.md и документы, на которые ссылается Issue. Проверь
текущее состояние кода и зависимости задачи.

Ожидаемый результат: [один проверяемый результат].
Границы: [что можно менять и что не входит в задачу].

Перед изменениями кратко напиши план, вход, выход и проверки. Затем реализуй
задачу в отдельной ветке, запусти подходящие проверки и покажи diff. Не коммить
секреты и реальные данные. Не меняй общий API, схему БД или зависимости без
согласования в Issue. Подготовь подробный английский commit message и описание PR.
```

## Проверка человеком

Перед merge владелец изменения должен уметь объяснить основной путь данных,
показать успешный сценарий и ожидаемую ошибку, а также подтвердить результаты
проверок. Сгенерированный код принимает команда, а не AI-помощник.
