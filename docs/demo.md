# Демо, измерение пользы и сдача

Черновик для Issue #13. Финальные числа и скриншоты заполняются только после
готовности общей цепочки #12.

## Главная история

Сотрудник сообщает в MAX о завершённом ремонте. Бот сохраняет исходное сообщение,
показывает AI-черновик и просит исправить или подтвердить его. Затем другой
сотрудник описывает похожий симптом. Бот находит только что подтверждённый случай,
показывает исходный текст, оборудование и участника ремонта. На неизвестную
проблему бот честно отвечает, что подтверждённого опыта нет.

## Сценарий показа

1. Показать пустой поиск по заранее выбранному новому симптому.
2. Отправить синтетическое сообщение о ремонте оборудования.
3. Показать AI-черновик, намеренно исправить одно поле и подтвердить случай.
4. От другого пользователя повторить поиск похожими, но не идентичными словами.
5. Открыть найденный случай, источник и участника.
6. Показать историю того же оборудования.
7. Отправить неизвестную проблему и показать честный пустой результат.

Основной проход должен укладываться в 2–3 минуты. Для сбоя сети или MAX хранится
резервная запись того же сценария и набор скриншотов с commit демо-версии.

## Мини-измерение пользы

Подготовить 15–20 синтетических сообщений и 5 поисковых задач. Не менее трёх
участников по очереди решают одинаковые задачи двумя способами: ручной просмотр
набора и поиск через бота. Порядок способов чередуется, чтобы первый проход не
давал одному варианту преимущество.

Для каждой попытки записываем:

| Поле | Значение |
| --- | --- |
| Код участника | Без имени |
| Код задачи | Одинаковый для двух способов |
| Способ | Ручной / бот |
| Время, секунды | От показа запроса до выбранного источника |
| Успех | Найден правильный подтверждённый случай: да/нет |
| Ошибка | Кратко, без персональных данных |

В презентации показываем медианное время и долю успешных попыток отдельно для
каждого способа, размер теста и условия. Не переносим результат маленького теста
на промышленную эксплуатацию и не обещаем снижение простоев без внедрения.

## Структура презентации

1. Пользователь и конкретный барьер: опыт остаётся в сообщениях и плохо находится.
2. Путь сейчас: ручной просмотр и вопросы коллегам.
3. Решение: сообщение → проверяемый черновик → подтверждённый случай → поиск.
4. Живое демо с новым знанием, которое появляется во время показа.
5. Почему результату можно доверять: источник, человек подтверждает, неизвестное
   остаётся пустым, поиск не выдаёт похожий случай за диагноз.
6. Измерение на синтетическом наборе и честные ограничения.
7. Следующие шаги: права, масштабирование данных, mini app только после bot MVP.
