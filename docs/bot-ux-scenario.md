## 1. Терминология и визуальные обозначения

| Обозначение | Значение |
|---|---|
| `[Кнопка]` | Inline-кнопка под сообщением бота |
| `👤 >` | Текст, который вводит пользователь |
| `🤖 >` | Сообщение бота |
| ⏳ | Индикатор загрузки (typing action) |
| 📝 | AI-черновик (не подтверждён) |
| ✅ | Подтверждённый случай |
| ⚠️ | Ошибка / предупреждение |

**Важно для пользователя:** бот всегда явно маркирует:
- `📝 Черновик` — результат AI, требует проверки человеком
- `✅ Подтверждённый случай` — проверен и сохранён сотрудником

## 3. Сценарий A — Сохранение опыта

### 3.1. Пользователь отправляет сообщение

Пользователь нажимает `[💾 Сохранить опыт]` в главном меню.

```
🤖 > Отправьте текст рабочего сообщения о ремонте или решённой проблеме.

      Пример:
      «На Н-204 выросла вибрация. Подтянули крепление муфты — вибрация ушла.»

      [⬅ Назад]
```

```
👤 > На Н-204 выросла вибрация. Подтянули крепление муфты — вибрация ушла.
```

### 3.2. Ожидание AI

Бот показывает typing indicator, затем отправляет промежуточное сообщение:

```
🤖 > ⏳ Анализирую сообщение…
```

> **Техническое (реализовано):** событие `message_created` принимает `app.bot.handler.MaxUpdateHandler`.
> Из сообщения берутся `mid` (становится `source.id` и `source.external_event_id`) и
> `sender.user_id` (становится `source.author_id` через `actor_from_max_event` — проверенная
> личность, утверждённая платформой MAX).
> Хранилище — `DbCaseService` (PostgreSQL), идемпотентность по `mid` — уникальный индекс в БД.
> AI-извлечение (#6) ещё не реализовано: поля `symptom`, `cause`, `action`, `result`, `participant`
> остаются `null` до появления AI-черновика. Typing action и `POST /api/cases` — план для #16.
> Таймаут запроса MAX API — 15 сек (`request_timeout_seconds` в `MaxBotSettings`).

### 3.3. AI-черновик — успех

```
🤖 > 📝 Черновик — проверьте и исправьте, если нужно:

      ⚙️ Оборудование: Н-204
      🔍 Симптом: Повышенная вибрация
      ❓ Причина: —
      🔧 Действие: Подтянули крепление муфты
      ✅ Результат: Вибрация исчезла
      👷 Участник: —

      Это черновик AI. Неизвестные поля оставлены пустыми.
      Проверьте данные перед подтверждением.

      [✅ Подтвердить]  [✏️ Исправить]  [🗑 Отменить]
```

> **Ключевые решения:**
> - «—» вместо пустоты, чтобы пользователь видел, какие поля не заполнены
> - Эмодзи-маркеры для чёткой визуальной структуры на мобильном экране
> - Явная подпись «Это черновик AI» отделяет AI от подтверждённого факта

### 3.4. Подтверждение

Пользователь нажимает `[✅ Подтвердить]`.

> **Валидация при подтверждении:** сервер требует заполнение `equipment` и хотя
> бы одного из `symptom` / `action` / `result`. Если условие не выполнено —
> см. [6.4 Неполный черновик](#64-неполный-черновик).
>
> **Права (реализовано):** исправлять и подтверждать черновик может только автор
> исходного сообщения (`source.author_id`). Попытка другого пользователя возвращает
> `403 case_forbidden` — см. [6.5 Отказ в доступе](#65-отказ-в-доступе-403-case_forbidden).
> `confirmed_by` сервер берёт из проверенной личности, не из тела запроса.

```
🤖 > ✅ Случай сохранён и теперь доступен в поиске.

      ⚙️ Оборудование: Н-204
      🔍 Симптом: Повышенная вибрация
      🔧 Действие: Подтянули крепление муфты
      ✅ Результат: Вибрация исчезла

      [🔎 Найти похожие]  [💾 Сохранить ещё]  [🏠 Меню]
```

### 3.5. Исправление

Пользователь нажимает `[✏️ Исправить]`.

```
🤖 > Что нужно исправить? Выберите поле:

      [Оборудование]  [Симптом]  [Причина]
      [Действие]  [Результат]  [Участник]
      [⬅ Назад к черновику]
```

Пользователь нажимает, например, `[Причина]`:

```
🤖 > Текущее значение причины: —

      Введите новое значение или отправьте «—» чтобы оставить пустым.

      [⬅ Назад к полям]
```

```
👤 > Ослабло крепление муфты
```

> **Техническое:** бот вызывает `PATCH /api/cases/{case_id}` с
> `{"cause": "Ослабло крепление муфты"}`.

```
🤖 > ✏️ Причина обновлена.

      📝 Черновик — проверьте и исправьте, если нужно:

      ⚙️ Оборудование: Н-204
      🔍 Симптом: Повышенная вибрация
      ❓ Причина: Ослабло крепление муфты
      🔧 Действие: Подтянули крепление муфты
      ✅ Результат: Вибрация исчезла
      👷 Участник: —

      [✅ Подтвердить]  [✏️ Исправить ещё]  [🗑 Отменить]
```

> Пользователь может исправлять несколько полей последовательно.
> Каждое исправление возвращает к обновлённому черновику.

### 3.6. Отмена

Пользователь нажимает `[🗑 Отменить]`.

```
🤖 > Черновик отменён. Исходное сообщение сохранено —
      вы можете отправить его снова в любой момент.

      [💾 Сохранить опыт]  [🔎 Найти опыт]  [🏠 Меню]
```

> **Техническое:** черновик помечается как отменённый или удаляется.
> Исходное сообщение (`source`) не теряется — повторная доставка того же `mid`
> не создаёт второй случай (уникальный индекс по `source_external_event_id` в БД).
> При повторе обработчик отправляет подтверждение снова (идемпотентный ответ).

## 4. Сценарий B — Поиск опыта

### 4.1. Пользователь вводит запрос

Пользователь нажимает `[🔎 Найти опыт]` в главном меню.

```
🤖 > Опишите проблему или укажите оборудование.

      Пример:
      «вибрация на насосе» или «Н-204»

      [⬅ Назад]
```

```
👤 > вибрация на насосе
```

### 4.2. Ожидание поиска

```
🤖 > ⏳ Ищу похожие случаи…
```

> **Техническое:** бот вызывает `GET /api/cases?q=вибрация на насосе&limit=5`.
> Сейчас поиск — плоский текстовый фильтр; similarity-поиск — Issue #8.

### 4.3. Результаты поиска — найдены

```
🤖 > 🔎 Найдено 2 подтверждённых случая:

      1️⃣ ✅ Насос Н-204 — Повышенная вибрация
         🔧 Подтянули крепление муфты
         📅 20.09.2026

      2️⃣ ✅ Насос Н-301 — Вибрация при запуске
         🔧 Заменён подшипник
         📅 18.09.2026

      Это подтверждённый опыт, а не диагноз.
      Выберите номер для подробностей.

      [1️⃣ Подробнее]  [2️⃣ Подробнее]
      [🔎 Новый поиск]  [🏠 Меню]
```

### 4.4. Карточка случая

Пользователь нажимает `[1️⃣ Подробнее]`:

```
🤖 > ✅ Подтверждённый случай

      ⚙️ Оборудование: Насос Н-204
      🔍 Симптом: Повышенная вибрация
      ❓ Причина: Ослабло крепление муфты
      🔧 Действие: Подтянули крепление муфты
      ✅ Результат: Вибрация исчезла
      👷 Участник: Смирнов
      📅 Дата: 20.09.2026

      💬 Источник: «Ремонтировал Н-204: вибрация
      из-за муфты, подтянул крепление, боец Смирнов
      помогал на месте.»

      [📜 История Н-204]  [⬅ К результатам]  [🏠 Меню]
```

### 4.5. История оборудования

Пользователь нажимает `[📜 История Н-204]`:

> **Техническое:** `GET /api/equipment/Н-204/history?limit=5` — возвращает только
> `confirmed` случаи. HTTP API требует проверенной личности (`401` без неё);
> из бота запрос идёт по внутренней сети, заголовок `X-Demo-User-Id` используется
> только при `ALLOW_DEMO_IDENTITY=1` (dev-окружение, не продакшен).

```
🤖 > 📜 История оборудования: Насос Н-204

      1. ✅ Повышенная вибрация → Подтянули крепление
         муфты (20.09.2026)

      2. ✅ Утечка сальника → Замена сальника
         (15.08.2026)

      [⬅ К случаю]  [🔎 Новый поиск]  [🏠 Меню]
```

### 4.6. Пустой поиск

```
🤖 > 🔎 Подтверждённых случаев по запросу
      «перегрев контроллера» не найдено.

      Возможно, такой опыт ещё не сохранён.
      Вы можете сохранить его сейчас.

      [💾 Сохранить опыт]  [🔎 Другой запрос]  [🏠 Меню]
```

## 5. Точка входа: стартовое сообщение и команды

### 5.1. Первый запуск / /start

```
🤖 > 👋 Привет! Я помогу сохранить и найти
      опыт решения проблем на оборудовании.

      Что вы хотите сделать?

      [💾 Сохранить опыт]  [🔎 Найти опыт]  [❓ Помощь]
```

### 5.2. Команды бота

| Команда | Действие |
|---|---|
| `/start` | Главное меню |
| `/save` | Перейти к сохранению опыта |
| `/search` | Перейти к поиску |
| `/help` | Список команд и краткая инструкция |
| `/cancel` | Отменить текущее действие, вернуться в меню |

### 5.3. Сообщение /help

```
🤖 > ❓ Как пользоваться ботом:

      💾 Сохранить опыт — отправьте текст о решённой
      проблеме, и AI поможет оформить его в карточку.
      Проверьте черновик и подтвердите.

      🔎 Найти опыт — опишите проблему, и бот покажет
      похожие подтверждённые случаи из опыта коллег.

      Команды:
      /save — сохранить опыт
      /search — поиск по опыту
      /cancel — отмена и возврат в меню

      [💾 Сохранить опыт]  [🔎 Найти опыт]
```

### 5.4. /cancel из любого состояния

```
🤖 > Действие отменено.

      [💾 Сохранить опыт]  [🔎 Найти опыт]  [❓ Помощь]
```

> `/cancel` работает из **любого** состояния диалога и возвращает
> в главное меню. Если был активный черновик, он сохраняется как
> `draft` — не теряется, но и не подтверждается.

## 6. Состояния ошибок и edge-cases

### 6.1. AI недоступен

AI (#6) не ответил за 15 секунд или вернул ошибку.

```
🤖 > ⚠️ Не удалось обработать сообщение —
      сервис анализа временно недоступен.

      Ваше сообщение сохранено и не потеряно.
      Попробуйте через минуту.

      [🔄 Повторить]  [🗑 Отменить]  [🏠 Меню]
```

> **Техническое:** исходное сообщение (`source`) уже сохранено в PostgreSQL
> при первом вызове — `mid` → `source_external_event_id` (уникальный индекс).
> При нажатии `[🔄 Повторить]` бот инициирует повторную AI-обработку **того же**
> случая (без дубликата по `external_event_id`).
> Повторная доставка события MAX также не создаёт дубликат —
> `DbCaseService` возвращает существующий случай и `created=False`.

### 6.2. Ошибка сервера (5xx)

```
🤖 > ⚠️ Произошла ошибка сервера. Попробуйте
      через несколько минут.

      [🔄 Повторить]  [🏠 Меню]
```

### 6.3. Ошибка валидации (422)

Пользователь отправил сообщение, которое сервер не принял.

```
🤖 > ⚠️ Не удалось обработать сообщение.
      Проверьте, что текст содержит описание
      проблемы или ремонта.

      [💾 Попробовать другое сообщение]  [🏠 Меню]
```

### 6.4. Неполный черновик

Пользователь нажимает `[✅ Подтвердить]`, но оборудование не заполнено
или отсутствуют `symptom`, `action` и `result` одновременно.

> **Техническое:** сервер возвращает `422` при `POST /confirm`.

```
🤖 > ⚠️ Для подтверждения нужно заполнить:
      — Оборудование (обязательно)
      — Хотя бы одно из: Симптом, Действие или Результат

      Пожалуйста, заполните недостающие поля.

      📝 Текущий черновик:

      ⚙️ Оборудование: —  ⬅ нужно заполнить
      🔍 Симптом: —
      🔧 Действие: —
      ✅ Результат: —

      [✏️ Исправить]  [🗑 Отменить]
```

### 6.5. Отказ в доступе (403 case_forbidden)

Пользователь пытается исправить или подтвердить черновик, созданный из чужого сообщения.

> **Реализовано:** `app.cases.permissions.ensure_may_modify` сравнивает
> `actor.user_id` с `source.author_id`; при несовпадении — `CaseForbiddenError` → HTTP `403`.

```
🤖 > ⚠️ Это черновик из чужого сообщения —
      изменить его может только его автор.

      [🏠 Меню]
```

### 6.6. Случай уже подтверждён (409 Conflict)

Попытка повторного подтверждения или исправления подтверждённого случая.

```
🤖 > ℹ️ Этот случай уже подтверждён, изменить
      его нельзя.

      [🔎 Найти опыт]  [💾 Сохранить новый]  [🏠 Меню]
```

### 6.7. Ошибка поиска

```
🤖 > ⚠️ Поиск временно недоступен. Попробуйте
      через минуту.

      [🔄 Повторить]  [🏠 Меню]
```

### 6.8. Пустая история оборудования

```
🤖 > 📜 По оборудованию «КА-107» подтверждённых
      случаев пока нет.

      [🔎 Найти по-другому]  [🏠 Меню]
```

### 6.9. Повторная отправка того же сообщения

Пользователь пересылает то же сообщение MAX с тем же `mid`.

> **Реализовано:** `DbCaseService.create` обнаруживает дубликат по уникальному
> индексу `source_external_event_id` и возвращает (`existing_case`, `created=False`).
> Обработчик отправляет тот же ответ с `case_id` ещё раз — восстановление после
> сбоя доставки. Возможен одинаковый ответ дважды, если первый дошёл, но клиент
> не подтвердил получение от MAX.

Если случай — черновик:

```
🤖 > ℹ️ Это сообщение уже обработано ранее.

      📝 Черновик:

      ⚙️ Оборудование: Н-204
      🔍 Симптом: Повышенная вибрация
      …

      [✅ Подтвердить]  [✏️ Исправить]  [🗑 Отменить]
```

Если случай уже подтверждён:

```
🤖 > ℹ️ Это сообщение уже обработано и подтверждено.

      [🔎 Найти похожие]  [💾 Сохранить другой]  [🏠 Меню]
```

### 6.10. Сообщение без текста

Пользователь отправил голосовое, фото, стикер или другой нетекстовый контент.

> **Реализовано:** `MaxUpdateHandler` проверяет `message.body.text`; пустой/отсутствующий текст
> возвращает `TEXT_ONLY_NOTICE` без создания случая. Случай не создаётся и запись в БД
> не происходит.

```
🤖 > Пока я понимаю только текстовые сообщения.
```

### 6.11. Неизвестный ввод в контексте

Пользователь вводит текст, когда бот ждёт нажатия кнопки.

```
🤖 > Не понял, что вы хотите сделать.
      Выберите действие с помощью кнопок ниже
      или используйте /help.

      [💾 Сохранить опыт]  [🔎 Найти опыт]  [❓ Помощь]
```

### 6.12. Два запущенных процесса polling

> **Ограничение транспорта:** два параллельных `app.bot.polling` с одним токеном
> начнут отбирать сообщения друг у друга — часть событий потеряется.
> Перед запуском бота на сервере остановить все локальные `polling`-процессы.
> Подробнее — `backend/app/bot/README.md`.

## 7. Синтетические примеры для проверки

Все примеры используют синтетические данные из `data/` и `contracts/`.

### Пример 1: Полный успешный путь (сохранение + поиск)

**Вход:** «На Н-204 выросла вибрация. Подтянули крепление муфты — вибрация ушла.»

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | Пользователь: `/save` | Бот просит ввести сообщение |
| 2 | Пользователь отправляет текст | Typing, затем черновик с `equipment: Н-204`, `cause: null` |
| 3 | Нажимает `[✏️ Исправить]` → `[Причина]` | Бот спрашивает значение |
| 4 | Вводит «Ослабло крепление муфты» | Обновлённый черновик с причиной |
| 5 | Нажимает `[✅ Подтвердить]` | «Случай сохранён» |
| 6 | Нажимает `[🔎 Найти похожие]` | Переход к поиску |
| 7 | Вводит «вибрация насоса» | Результат: случай из шага 5 |

### Пример 2: Неполное сообщение

**Вход:** «Проблема решена, всё работает»

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | Пользователь отправляет текст | AI-черновик: все поля `null` кроме `result: "Всё работает"` |
| 2 | Нажимает `[✅ Подтвердить]` | Ошибка 422: нет оборудования и полей |
| 3 | Нажимает `[✏️ Исправить]` → `[Оборудование]` | Вводит «ТА-105» |
| 4 | Нажимает `[✏️ Исправить ещё]` → `[Действие]` | Вводит «Заменили прокладку» |
| 5 | Нажимает `[✅ Подтвердить]` | Успех |

### Пример 3: AI недоступен → повтор

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | Пользователь отправляет текст | Typing 15 сек, затем ⚠️ AI недоступен |
| 2 | Ждёт, нажимает `[🔄 Повторить]` | Typing, затем AI-черновик (если AI поднялся) |
| 3 | Или нажимает `[🗑 Отменить]` | Возврат в меню, сообщение не потеряно |

### Пример 4: Пустой поиск

**Вход:** «перегрев контроллера»

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | `/search` → «перегрев контроллера» | «Подтверждённых случаев не найдено» |
| 2 | Нажимает `[💾 Сохранить опыт]` | Переход к сохранению |

### Пример 5: Повторная отправка

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | Пользователь пересылает ранее обработанное сообщение | «Это сообщение уже обработано» + черновик / подтверждённый |

### Пример 6: Мобильный экран MAX — длинное сообщение

**Вход:** «Позавчера работал на Н-204, была повышенная вибрация,
нашли что крепление муфты ослабло, подтянули, вибрация ушла,
Смирнов помогал мне на месте, деталь была в запасе на складе»

| Проверка | Ожидание |

| Черновик помещается на экран ~360px без горизонтальной прокрутки | Да, текст переносится по словам |
| Кнопки не обрезаются | Да, кнопки расположены строками по 2-3 |
| Длинные значения полей не ломают вёрстку | Значение переносится на следующую строку |

## 8. Требования к боту и backend

### Переменные окружения (реализовано в `app.bot.settings`)

| Переменная | Назначение | Статус |
|---|---|---|
| `MAX_BOT_TOKEN` | Токен бота. `SecretStr` — не попадает в логи. | ✅ реализовано |
| `MAX_API_CA_BUNDLE` | Путь к CA-бандлу с Russian Trusted Root CA. | ✅ реализовано |
| `MAX_API_BASE_URL` | Адрес API (по умолчанию `https://platform-api2.max.ru`). | ✅ реализовано |
| `ALLOW_DEMO_IDENTITY` | Разрешает `X-Demo-User-Id` в HTTP API. В проде — **не ставить**. | ✅ реализовано |
| `DATABASE_URL` | PostgreSQL DSN. | ✅ реализовано |

### Что должен уметь бот (Андрей)

| Возможность | API-вызов / модуль | Статус | Комментарий |
|---|---|---|---|

| Игнорировать нетекстовые сообщения | `app.bot.handler` | ✅ реализовано | `TEXT_ONLY_NOTICE` без создания случая |
| Идемпотентность по `mid` | `DbCaseService` / индекс БД | ✅ реализовано | `created=False` при повторе |
| Подтверждение приёма отправителю | `MaxClient.send_text` | ✅ реализовано | Заглушка — формулировки (#16) |

### Callback data для кнопок

```
confirm:{case_id}
edit:{case_id}
edit_field:{case_id}:{field_name}
cancel:{case_id}
search_detail:{case_id}
equipment_history:{equipment_id}
back_to_results
back_to_draft:{case_id}
back_to_fields:{case_id}
new_search
new_save
menu
```

> Формат `action:param` — рекомендация; Андрей может адаптировать
> под ограничения API бота MAX (callback_data до 64 байт).

### Ограничения транспорта (long polling)

> Из `backend/app/bot/README.md` — важно для #16:
> - Режим long polling задокументирован платформой как dev-режим: ограничен по скорости и хранению.
> - Long polling и webhook взаимоисключающие: при активной подписке webhook `/updates` не работает.
> - Не более 30 запросов в секунду.
> - **Один процесс polling с токеном:** параллельные запуски крадут сообщения друг у друга.
> - Маркер сдвигается только после успешной обработки всего батча (ошибка → без потери).
> - Переход на webhook: `POST /subscriptions` без изменения `MaxUpdateHandler`.

## 9. Статус реализации транспортного слоя

> Раздел отражает состояние на 25.09.2026. ✅ — реализовано в `develop`.

### Транспорт и идентичность

- [x] Бот принимает `message_created` через long polling (`app.bot.polling`)
- [x] Токен — `SecretStr`, не попадает в логи и traceback
- [x] TLS с Russian Trusted Root CA: бандл в образе, `MAX_API_CA_BUNDLE`
- [x] Игнорируются события от ботов и события без отправителя
- [x] Сообщение без текста: короткий ответ, случай не создаётся
- [x] `sender.user_id` из MAX-события → `source.author_id` (проверенная личность)
- [x] Маркер polling сдвигается только после успешного батча
- [ ] Переход на webhook (ждёт публичного HTTPS — Issue #11)

### Хранилище

- [x] Случаи хранятся в PostgreSQL (`DbCaseService`)
- [x] Повторный `mid` не создаёт дубликат (уникальный индекс `source_external_event_id`)
- [x] `created=False` при повторной доставке; подтверждение отправляется снова
- [x] Права: исправлять и подтверждать — только автор исходного сообщения (→ `403`)
- [x] HTTP API без проверенной личности → `401` (нет `ALLOW_DEMO_IDENTITY` в проде)

### API для диалогового слоя (#16)

- [x] `POST /api/cases` — создание случая (принимает `source` от бота)
- [x] `PATCH /api/cases/{id}` — частичное обновление полей черновика
- [x] `POST /api/cases/{id}/confirm` — подтверждение (личность из события, не заголовка)
- [x] `GET /api/cases?q=` — текстовый поиск (только `confirmed`)
- [x] `GET /api/equipment/{id}/history` — история (только `confirmed`)
- [x] `409 Conflict` при повторном подтверждении подтверждённого случая
