# MAX, развёртывание и сдача

## Требования документа трека «Эффективный бизнес»

Страницы 9–11 документа организаторов уточняют комплект сдачи. Обязательны:
работающий бот в MAX для проверки основного сценария; зафиксированный Git commit
или архив исходников с контрольной суммой; README с архитектурой, окружением,
данными, запуском и пошаговой проверкой; файл зависимостей; Dockerfile,
`compose.yaml`, `.dockerignore`, `.env.example`; **презентация в PDF**. Без
презентации проект получает 0 и дальше не оценивается.

На первом, служебном слайде PDF требуются ссылка на бота, репозиторий и commit,
адрес собственного API (если есть), тестовые доступы, значения окружения,
необходимые для проверки, и краткий сценарий. Организаторы упоминают рабочие
токены и API-ключи: их нельзя размещать в Git или публичных материалах. Перед
отправкой команда должна решить, как передать необходимые для проверки значения
через закрытую форму личного кабинета и кому будет доступен этот PDF.

По странице 10 собственный API не обязателен. Если команда заявляет внешний
HTTP API частью продукта, дополнительно нужны HTTPS-адрес, OpenAPI 3.0/3.1,
тестовые учетные записи и данные, `DATA-API.yaml`. Основной продукт команды —
чат-бот MAX; внутренний API случаев не предлагается жюри как отдельный продукт.

На скриншоте личного кабинета загрузка принимает PDF, PPT, CSV или архив при
наличии приложения, **до 18 МБ**. Несмотря на возможность загрузить PPT, документ
трека требует именно PDF-презентацию. Итоговый файл и наличие всех ссылок нужно
проверить до 30 сентября, 12:00 МСК.

По сообщению организаторов, которое команда получила 21 сентября, онлайн-тур
идёт с 15 по 30 сентября 2026 года. За это время нужно разработать концепцию и
создать чат-бота **или** мини-приложение. Оценка проектов проходит с 30 сентября
по 14 октября, финал — 29 октября в Казани.

По FAQ организаторов решение сдаётся **до 30 сентября 2026 года, 12:00 МСК, в
личном кабинете**. Переданная версия фиксируется и не меняется. Рабочий бот
должен оставаться доступным во время оценки. Внутренний дедлайн команды —
29 сентября: к этому дню фиксируем рабочую версию и материалы.

Чат-бот без мини-приложения допустим. Синтетические данные и модельные интеграции
следует явно обозначить в README и презентации; внешние API должны быть
документированными. Подробнее: [FAQ](https://cloud.mail.ru/public/THoi/7pmGKgDYK).

## Уточнить у организаторов

- Точные поля загрузки в личном кабинете и доступ экспертов к файлу.
- Публичность репозитория и способ доступа жюри к приватному репозиторию.
- Разрешено ли использовать ранее написанные компоненты.
- Нужно ли отдельно передавать ссылку на чат-бота и где это сделать.
- Если успеем сделать мини-приложение: когда обрабатывается форма URL и можно ли
  обновлять URL и содержимое приложения.

## Выбранный формат

Обязательный MVP — чат-бот MAX. Ввод сообщения, проверка AI-черновика,
подтверждение и поиск похожего случая должны проходить в диалоге с ботом.
Мини-приложение и форма для его URL отложены до готовности и стабилизации этого
сценария. Форма не нужна для bot-only MVP, если организаторы не сообщат обратное.

## Опциональное мини-приложение

Если останется время, frontend размещается по HTTPS и привязывается к боту MAX.
Полученный токен используется только сервером. Назначение формы ниже предполагается
по её названию; её содержание и точный процесс организаторов ещё не подтверждены.
